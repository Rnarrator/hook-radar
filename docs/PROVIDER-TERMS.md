# Data providers and their terms

The Auto Snapshot edition collects its data from public services. This page says which ones, what each is used for, what is known about their terms, and what you should settle **before you announce the site**.

Read this first: it was written without contacting any provider, from what the project understood when the edition was built. Terms and limits change. It is a checklist, not legal advice, and the providers' own pages decide. Where something has not been verified, it says so.

The site's page does not credit them: at your choice it shows no provider credit and no Data and sources dialog. Read the next section before you announce the site.

## Credit on the page: your choice, and your responsibility

At your choice, the page of this edition shows **no provider credit and no Data and sources dialog**. In detail: the footer has no credit line (no "Prices from ..." sentence with links) and no line about protocol logos with a link to the third-party notices; the header has no Data and sources button; and the "Data details", "View data coverage", "Data sources" and "Sources and coverage details" buttons are not there. The notices file, `public/third-party-notices.txt`, is still published at `/third-party-notices.txt`; while the credit is off, nothing on the page links to it.

GeckoTerminal's terms ask for a visible credit link. The terms of the other providers must be read for what they ask. You are responsible for whatever attribution the providers require, and the page, as it stands, gives none: settle that before you announce the site, either by bringing the credit back or by giving the credit in the way each provider's terms allow.

To bring the dialog and the credits back, change one line in `src/edition.ts`: `export const EDITION_SOURCES_DIALOG: boolean = false;` becomes `export const EDITION_SOURCES_DIALOG: boolean = true;`. Then build the site again. The header button, the dialog and every button that opens it, the footer's credit line and its notices line all return, and nothing else changes. The dialog's code is still in the project; only its way in is switched off. The browser tests follow the line: with `true` they expect the dialog and the credits where they otherwise check that they are absent.

## How the collector behaves toward them

- It identifies itself with a truthful User-Agent that names the project and the repository it runs from, so a provider can see who is asking and contact you.
- It keeps the gaps above between requests to the same provider. They can be made longer through environment variables, never shorter.
- It honours `Retry-After` and never hammers. After the first 429 that says how long to wait (a `Retry-After` in seconds or as a date, or Cloudflare's rate-limit page, taken as 30 seconds), DEX Screener, GeckoTerminal or the v4.xyz indexer gets **one cooldown per run**: the collector waits that time (at most 90 seconds), sends the refused request one more time and doubles that provider's gap for the rest of the run. A second 429, a 429 that names no wait, a longer wait and any 403 stop using that provider for the rest of the run. It retries nothing else, and the registry, Frontier and Goldsky requests get no cooldown at all: their first 429 stops them. The quality gate then decides whether what was collected is good enough to publish; if not, nothing is published.
- The 7D and 30D step (`collector/daily.mjs`) is the last step of a run and uses the same GeckoTerminal lane: the same gap, the same single cooldown, and the same 399-request limit, spending only what the rest of the run left. It sends at most 20 requests, none starting later than four minutes into the step, reads a pool about twice a day, and is skipped when GeckoTerminal was stopped earlier in the run. `COLLECTOR_DAILY_MAX_REQUESTS` can lower the 20, and `0` turns it off; the gaps cannot be lowered.
- A whole run makes fewer than 400 requests. The Frontier step is three of them: the coin listing, the statistics and one index query. It starts at most four minutes into the burst, so the five-minute rule holds for the whole snapshot, and if it fails the run goes on without it: the pools of Frontier's hooks keep the figures the other providers returned.
- How often a run collects follows from the workflow: it is started three times an hour, but only the first start that finds the last snapshot at least 45 minutes old collects (and none within 90 minutes of a failed run), so at most 24 runs collect in a day. A run that only measures the pools already known makes up to about 300 requests, nearly all of them to DEX Screener, and none to the v4.xyz indexer; at most one run in each three-hour block also looks for new pools and makes up to about 80 more (about 60 of them to the v4.xyz indexer). In a day that is up to about 7,200 requests when a run collects in each hour, plus about 640 for the up to eight runs that look for new pools. These are the collector's own limits for a day on which GitHub starts every run, not measurements; the snapshot records the real count of each run. The optional external timer ([EXTERNAL-TRIGGER.md](EXTERNAL-TRIGGER.md)) asks only GitHub and the same gate decides, so a call adds no request to a provider by itself: a new snapshot is still not taken less than 45 minutes after the last one was saved.
- It uses no API keys and no accounts. The site itself never contacts a provider; visitors download static files.

## What to do before launching publicly

1. **Ask the v4.xyz maintainers for permission**, in writing, to read those two paths on a schedule. The paths are not documented as public, so they can change or close without notice. To ask, start from www.v4.xyz and ask in writing. If they say no, or you want to wait for their answer first, there is a one-line edit that needs no code. Make it before you switch on GitHub Pages, because once Pages is on the job also starts by itself within the hour, not only when you press Run workflow. On github.com open `.github/workflows/snapshot.yml`, press the pencil icon, change the line `run: node collector/run.mjs` (the step named "Collect the snapshot") to `run: node collector/run.mjs --max-discovery 0`, and commit. This stops all discovery and every v4.xyz request. The site keeps measuring the pools it already knows through DEX Screener but stops learning new ones, and the quality gate still decides whether each snapshot may be published. (The FTPS route has the same Collect line in `deploy-ftp.yml`; make the edit there before its first run.) When they agree, open the same file, press the pencil icon, change the line back to `run: node collector/run.mjs` and commit; until you do, the site does not learn new pools.
2. **Read GeckoTerminal's and CoinGecko's current API terms.** GeckoTerminal's terms ask for a visible credit link, and the page shows none while the credit is switched off (see "Credit on the page" above): check which wording they ask for, and settle where it appears before you announce the site. Decide whether scheduled use at this size is acceptable under the free keyless interface or whether you should ask for an agreement or a key. If you ever add a key, store it as a repository secret, never in a file.
3. **Read DEX Screener's current terms.** Check what they say about showing figures derived from its data on a public site, about reselling or republishing data, and about ending access. If access ever ends, the collector will fail its quality gate, nothing new will be published and the site will keep showing its last dated snapshot. Decide in advance what you will do then.
4. **Check the licence of the Uniswap hooklist** and ask the maintainers of the Frontier endpoints, and of the public index they name (Goldsky hosts it), whether reading them on a schedule is fine.
5. **Look at the live page.** The snapshot date must be at the top and figures must carry their scope labels. The page gives the providers no credit while the credit is switched off (see "Credit on the page" above), so check where each provider asks to be credited, and that it is.
6. **Keep contact details current** on the repository, since the User-Agent points providers at it.
7. **Do not imply endorsement.** Names, logos and marks belong to their owners. The site shows verified original logos only, as a way of identifying projects, and never says or suggests that a project, Uniswap or a data provider sponsors the site. Whatever licence you choose for the code (see the steps in README.md) covers your code only: the data stays under the providers' terms and the logos belong to their owners.

## If a provider asks you to stop

Disable the Snapshot workflow (Actions, Snapshot, the three dots, Disable workflow). If you use the external timer ([EXTERNAL-TRIGGER.md](EXTERNAL-TRIGGER.md)), switch it off too, so that nothing is left running unattended. The site stays up with its last snapshot and its date, so nobody is shown a figure as current when it is not. On the FTPS route, disable "Deploy to Namecheap by FTPS" the same way, or set the variable `ENABLE_FTP_DEPLOY` to anything but `true`.

If the provider is the v4.xyz indexer, make the one-line edit in item 1 above before you enable the workflow again, and change the line back only when they agree. For any other provider, someone who works on the code has to remove it from the collector (`collector/config.mjs` lists the hosts) before you enable the workflow again.
