# Data providers and their terms

The Auto Snapshot edition collects its data from public services. This page says which ones, what each is used for, what is known about their terms, and what you should settle **before you announce the site**.

Read this first: it was written without contacting any provider, from what the project understood when the edition was built. Terms and limits change. It is a checklist, not legal advice, and the providers' own pages decide. Where something has not been verified, it says so.

**Not used:** DefiLlama and the CoinGecko price APIs. This edition does not call them at all.

The exact hosts and gaps are in `collector/config.mjs`. The Data and sources dialog and the footer of the site name every provider that actually supplied data in the current snapshot, with a link, and the snapshot itself records how many requests each provider received and when.

## How the collector behaves toward them

- It identifies itself with a truthful User-Agent that names the project and the repository it runs from, so a provider can see who is asking and contact you.
- It keeps the gaps above between requests to the same provider. They can be made longer through environment variables, never shorter.
- It honours `Retry-After` and never hammers. After the first 429 that says how long to wait (a `Retry-After` in seconds or as a date, or Cloudflare's rate-limit page, taken as 30 seconds), DEX Screener, GeckoTerminal or the v4.xyz indexer gets **one cooldown per run**: the collector waits that time (at most 90 seconds), sends the refused request one more time and doubles that provider's gap for the rest of the run. A second 429, a 429 that names no wait, a longer wait and any 403 stop using that provider for the rest of the run. It retries nothing else, and the registry and Frontier fetches get no cooldown at all: their first 429 stops them. The quality gate then decides whether what was collected is good enough to publish; if not, nothing is published.
- A whole run makes fewer than 400 requests.
- It uses no API keys and no accounts. The site itself never contacts a provider; visitors download static files.

## What to do before launching publicly

1. **Ask the v4.xyz maintainers for permission**, in writing, to read those two paths on a schedule. The paths are not documented as public, so they can change or close without notice. To ask, start from www.v4.xyz (the same link the site's Data and sources dialog shows) and ask in writing. If they say no, or you want to wait for their answer first, there is a one-line edit that needs no code. Make it before you switch on GitHub Pages, because once Pages is on the job also starts by itself within three hours, not only when you press Run workflow. On github.com open `.github/workflows/snapshot.yml`, press the pencil icon, change the line `run: node collector/run.mjs` (the step named "Collect the snapshot") to `run: node collector/run.mjs --max-discovery 0`, and commit. This stops all discovery and every v4.xyz request. The site keeps measuring the pools it already knows through DEX Screener but stops learning new ones, and the quality gate still decides whether each snapshot may be published. (The FTPS route has the same Collect line in `deploy-ftp.yml`; make the edit there before its first run.) When they agree, open the same file, press the pencil icon, change the line back to `run: node collector/run.mjs` and commit; until you do, the site does not learn new pools.
2. **Read GeckoTerminal's and CoinGecko's current API terms.** Check which attribution wording they ask for and confirm that what the site shows (the Data and sources dialog and the footer) matches it. Decide whether scheduled use at this size is acceptable under the free keyless interface or whether you should ask for an agreement or a key. If you ever add a key, store it as a repository secret, never in a file.
3. **Read DEX Screener's current terms.** Check what they say about showing figures derived from its data on a public site, about reselling or republishing data, and about ending access. If access ever ends, the collector will fail its quality gate, nothing new will be published and the site will keep showing its last dated snapshot. Decide in advance what you will do then.
4. **Check the licence of the Uniswap hooklist** and ask the maintainers of the Frontier endpoint whether reading it on a schedule is fine.
5. **Look at the live page.** The provider names and links must be visible, the snapshot date must be at the top, and figures must carry their scope labels.
6. **Keep contact details current** on the repository, since the User-Agent points providers at it.
7. **Do not imply endorsement.** Names, logos and marks belong to their owners. The site shows verified original logos only, as a way of identifying projects, and never says or suggests that a project, Uniswap or a data provider sponsors the site. Whatever licence you choose for the code (see the steps in README.md) covers your code only: the data stays under the providers' terms and the logos belong to their owners.

## If a provider asks you to stop

Disable the Snapshot workflow (Actions, Snapshot, the three dots, Disable workflow). The site stays up with its last snapshot and its date, so nobody is shown a figure as current when it is not. On the FTPS route, disable "Deploy to Namecheap by FTPS" the same way, or set the variable `ENABLE_FTP_DEPLOY` to anything but `true`.

If the provider is the v4.xyz indexer, make the one-line edit in item 1 above before you enable the workflow again, and change the line back only when they agree. For any other provider, someone who works on the code has to remove it from the collector (`collector/config.mjs` lists the hosts) before you enable the workflow again.
